# Alpha Quester — Full Rebuild Guide (for the agent in a NEW project)

You are rebuilding this exact app in a fresh Lovable project from this repo's code.
The old backend is gone/paused; no data carries over. Follow every step in order.

## 1. What the app is
- Arabic (RTL) web app that auto-solves Discord Quests using users' Discord tokens.
- UI text in Arabic, numbers in English, font Tajawal. Bento grid, purple-blue on warm navy, white waves pattern.
- Hide the Lovable badge (#lovable-badge) — already handled in code.
- Flow: user signs up (email/password) → enters 16-char premium code (`/verification`) → adds Discord tokens → dashboard lists quests → solver runs them (heartbeats) → auto-claim at 100%.
- Auto-Quest: cron every 3 min scans all tokens of users with `profiles.auto_quest_enabled = true`, auto-enrolls quests, pulses progress in parallel.
- Supported tasks: WATCH_VIDEO, WATCH_VIDEO_ON_MOBILE (+8s per beat max), PLAY_ON_DESKTOP, STREAM_ON_DESKTOP, PLAY_ACTIVITY. ACHIEVEMENT_IN_ACTIVITY is unsupported (server-side only).
- Pages: Landing, Auth, Verification, Dashboard, QuestSolver, QuestHistory, Stats, Badges, Settings (webhook), AutomationCenter (`/dashboard/automation`), AdminCodes, UpdateMe.

## 2. Steps
1. Enable **Lovable Cloud**. Enable email/password auth (no auto-confirm unless the owner asks).
2. Apply every file in `supabase/migrations/` **in filename order, byte-for-byte** via the migration tool. They create tables, RLS, grants, functions (`sweep_stale_quest_sessions`, `purge_old_quest_data`) and two cron jobs.
3. Enable extensions if a migration fails: `pg_cron`, `pg_net`.
4. Deploy ALL edge functions in `supabase/functions/`:
   admin-codes, auto-quest, automation-control, discord-user-info, fetch-quests, pause-quest, public-stats, quest-heartbeat, quest-lab, start-quest, verify-subscription, video-quest-test, webhook-notify, webhook-settings.
   Keep `supabase/config.toml` `verify_jwt = false` entries (replace `project_id` with the new one — it's auto-generated).
5. Add the extra cron jobs (not in migrations — run via SQL, replace `<URL>` and `<ANON_KEY>` with the new project's values):
```sql
select cron.schedule('auto-quest-check','*/3 * * * *',$$select net.http_post(url:='<URL>/functions/v1/auto-quest',headers:='{"Content-Type":"application/json","Authorization":"Bearer <ANON_KEY>"}'::jsonb,body:='{"action":"check"}'::jsonb)$$);
select cron.schedule('auto-quest-heartbeat','* * * * *',$$select net.http_post(url:='<URL>/functions/v1/auto-quest',headers:='{"Content-Type":"application/json","Authorization":"Bearer <ANON_KEY>"}'::jsonb,body:='{"action":"heartbeat"}'::jsonb)$$);
select cron.schedule('webhook-notify-hourly','0 * * * *',$$select net.http_post(url:='<URL>/functions/v1/webhook-notify',headers:='{"Content-Type":"application/json","Authorization":"Bearer <ANON_KEY>"}'::jsonb,body:='{"action":"notify_all"}'::jsonb)$$);
```
   Check `supabase/functions/webhook-notify/index.ts` for the exact action name it expects before scheduling.
6. Secrets: only `Token_Test` (optional, a Discord token for testing). SUPABASE_* are automatic.
7. Regenerate types, check the build, sign up, test the flow.

## 3. Database tables
- `profiles` — user_id, auto_quest_enabled, total_solved_quests, subscription state.
- `discord_tokens` — user_id, encrypted_token, discord_username, is_active. **Never expose `encrypted_token` to the client (no SELECT for authenticated).**
- `quest_sessions` — quest runs: status running/pending/completed/failed/stopped, progress, target, method, last_beat_at, error_message. `[AUTO]` prefix in quest_name = auto runs.
- `quest_logs` — session_id, user_id, message, level.
- `subscription_codes` — 16-char premium codes generated by admins.
- `webhook_settings` — **never expose `webhook_url` to client.**
Edge functions use the service role; send actions in POST body as `{ action: "..." }`, not HTTP methods.

## 4. Admin
- No roles table: admin is a hardcoded email allowlist in BOTH `src/pages/AdminCodes.tsx` and `supabase/functions/admin-codes/index.ts`:
  `ADMIN_EMAILS = ["sf1@sf1.sf1", "uwu@alpha.dcq"]`
- Only those emails may generate codes. To make an account admin: sign up with one of those emails (or edit both lists identically). The server check is the real gate.
- First admin needs no code: generate codes from `/dashboard/admin` (check App.tsx for the exact path), then use one on `/verification`.

## 5. Discord rules learned
- Enroll: `POST /quests/{id}/enroll` body `{location: 11}` (+ sealed metadata if present).
- Video: `POST /quests/{id}/video-progress {timestamp}` — never jump more than ~8s ahead of real elapsed time.
- Desktop/stream/activity: `POST /quests/{id}/heartbeat {stream_key:"call:{dmChannelId}:1", terminal:false}`.
- Claim: `POST /quests/{id}/claim-reward {platform:0|1|2, location:11}`.
- Use the spoofed desktop-client headers in the functions as-is.
